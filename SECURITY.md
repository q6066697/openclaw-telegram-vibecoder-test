# Security

Как в этом проекте обрабатываются секреты и ограничивается доступ к боту.

## 1. Секреты — только через env, никогда в git

Ни один секрет (API-ключи, токен бота, пароль прокси, gateway-токен) не хранится в
репозитории и не попадает в коммиты. Всё приходит из переменных окружения или из
локального `.env`, который явно исключён в `.gitignore`:

```
*.env
.env
gateway.systemd.env
*.token
openclaw.json
openclaw.json.bak
```

Проверка перед каждым коммитом:

```bash
git status
git diff --cached --stat
```

Если в `git status` внезапно появился `.env`, `openclaw.json` или файл с секретом —
не коммитить, сначала разобраться (`git rm --cached <файл>` при необходимости).

Основные переменные окружения этого проекта:

| Переменная            | Назначение                                   |
| ---------------------- | --------------------------------------------- |
| `OPENAI_API_KEY`       | ключ модели (OpenAI)                          |
| `TELEGRAM_BOT_TOKEN`   | токен бота от BotFather                       |
| `HTTPS_PROXY`          | `http://user:pass@vds-host:port` — обход гео-блока |
| `OPENCLAW_GATEWAY_TOKEN` | (опционально) shared-токен для Gateway auth  |

Реальные значения живут только в `.env` на машине разработчика/сервера — сам файл
никогда не коммитится (см. `scripts/start.sh`).

## 2. SecretRef для gateway-токена

`openclaw.json` не хранит токен Gateway как plain-text. Он ссылается на системное
secret-хранилище OpenClaw через SecretRef:

```json
"gateway": {
  "auth": {
    "mode": "token",
    "token": "${secret:store:default:GATEWAY_TOKEN}"
  }
}
```

Сам `openclaw.json` тоже в `.gitignore` — в репозитории лежит только пример без
секретов: [`config/openclaw.example.json`](config/openclaw.example.json), где вместо
значений — плейсхолдеры вида `${secret:store:default:...}` или `<PLACEHOLDER>`.

Почему SecretRef, а не переменная окружения напрямую в конфиге:
- значение никогда не сериализуется в файл конфига, даже случайно (бэкапы
  `openclaw.json.bak*`, экспорт конфига, логи `config get`);
- `openclaw doctor` / `openclaw security` умеют проверять состояние ссылки
  (валидна/просрочена/отсутствует), не раскрывая сам секрет;
- ротация токена не требует правки конфигурационного файла.

## 3. Basic Auth на прокси

`tinyproxy` на VDS слушает не анонимно — доступ ограничен двумя уровнями
(см. [`scripts/setup-proxy.sh`](scripts/setup-proxy.sh)):

1. **Basic Auth** (`BasicAuth <user> <pass>` в `tinyproxy.conf`) — без логина/пароля
   запрос через прокси отклоняется.
2. **IP allowlist** (`Allow <IP-адрес-клиента>`) — прокси принимает соединения только
   с известного адреса машины/сервера, где крутится Gateway; всё остальное — `Deny all`.

Логин и пароль передаются процессу OpenClaw только через `HTTPS_PROXY` в
переменных окружения (`.env` → `scripts/start.sh`) и никогда не пишутся в
`tinyproxy.conf` в открытом виде в репозитории — конфиг генерируется скриптом
на самом VDS из плейсхолдеров/env, сам файл конфигурации прокси в репозиторий
не коммитится.

## 4. Telegram: pairing и owner-политика

Бот не выполняет команды от произвольных пользователей Telegram:

- **Pairing.** При первом обращении незнакомый чат должен пройти spairing —
  `openclaw pairing approve telegram <код>` подтверждает конкретный chat/user id
  вручную. Без подтверждения агент не отвечает на управляющие команды.
- **Owner allowlist.** `commands.ownerAllowFrom` в `openclaw.json` — явный список
  `telegram:<user_id>`, которым разрешено выполнять привилегированные команды
  (например, `/exec`-подобные действия агента). Все остальные отправители
  ограничены обычным диалогом, без доступа к системным операциям.

```json
"commands": {
  "ownerAllowFrom": ["telegram:<owner_user_id>"]
}
```

Это разделение — "кто может писать боту" (Telegram сам по себе публичный) и
"кто может отдавать агенту команды с побочными эффектами" (только owner из
allowlist) — минимизирует ущерб от того, что бот в принципе достижим извне.

## 5. Отчёт об уязвимостях

Это учебный/демонстрационный репозиторий (тестовое задание), не production-сервис.
Если вы нашли проблему в подходе (не в самом OpenClaw — баги OpenClaw репортить
в апстрим), откройте issue в этом репозитории с описанием и, если возможно,
шагами воспроизведения без публикации реальных секретов/токенов.
